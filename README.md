1.	Краткое описание Telegram-бота для работы с пользовательскими рекомендациями в различных категориях
  Цель: Создать чат-бота для Telegram, позволяющего пользователям вести (искать по id/ключевому  слову, изменять название, удалять категорию без чужих рекомендаций,  дополнять) общий иерархический каталог категорий, добавлять, изменять, удалять свои рекомендации по разным произведениям в  привязке к выбранной категории, искать рекомендации в выбранной категории по ее id или  ключевому слову
 Функционал:
  - Приветственное сообщение по команде /start с информацией о возможностях бота и меню.
  - При запуске бота в первый раз – инициализация начальной версии категорий
 - /list_cat - команда для просмотра иерархии категорий и количества сделанных в них рекомендаций
 (всего и своих).
 - /find_cat - команда для операций над категориями:  вначале – отбор категории по id или ключевому
 слову или операции выбора, после чего выбор действия над ней, в т.ч. просмотр подкатегорий и
 статистики сделанных рекомендаций всего/своих, добавить рядом,  добавить/исправить/удалить
 (при отсутствии чужих рекомендаций в данной категории и ее подкатегориях) подкатегорию.
 - /add - команда для добавления рекомендации: вначале отбор категории, потом – добавление
 рекомендации по ней.
 - /edit - команда для поиска и исправления своей рекомендации в нужной категории: вначале отбор
 категории, потом – отбор рекомендаций в ней по id/ключевому слову, после отбора конкретной своей
 рекомендации - выборочное рекомендации наименования или самой рекомендации.
 - /find - команда для поиска (по id или ключевому слову) рекомендаций в нужной категории (отбор
 нужной категории делается вначале) и последующих действий над выбранной рекомендацией:
 исправление/удаление (если своя).
 Особенности реализации:
 Все процессы реализованы в виде FSM -  автомата, для его реализации создан специальный класс, в котором каждого процесса определены свои статусы (состояния), возможные переходы из статуса в статус, сопутствующие статусам переменные, функции перехода из статуса в статус с формированием стека переходов и возврата назад с восстановлением из стека состояния процесса. Внутри класса также входит ведение лога и некоторые операции с базой данных.
 Реализовано всего 2 обработчика состояний (для того, чтобы их логика была более читабельной и, соответственно, более легко отлаживалась) – один отвечает за нажатие пользователем кнопок, формируемых ботом по логике процессов, второй – за ввод ответов пользователем на вопросы бота согласно логики процессов, причем часто в процессах одно и второе предоставляется  одновременно.
2.	Описание архитектуры Telegram-бота для пользовательских рекомендаций
- Ядро бота:  
  Бот реализован на Python с использованием библиотеки python-telegram-bot. Основная логика процессов реализована с помощью специального класса FSM (Finite State Machine), хранящего статус пользователя и стек переходов.
- Взаимодействие с Telegram:  
  Для обработки команд и сообщений используются Updater и Dispatcher, а для обработки кнопок — CallbackQueryHandler.
- База данных:  
  В качестве хранилища используется SQLite (через стандартную библиотеку sqlite3). В базе хранятся:
  - Пользовательские данные
  - Категории (иерархическая структура)
  - Рекомендации (привязаны к категориям и пользователям)
- Организация процессов:  
  Все пользовательские сценарии реализованы как процессы FSM с собственными статусами, переменными и переходами. Есть два основных обработчика:
  - Для кнопок (CallbackQuery)
  - Для текстовых ответов (Message)
- Логирование:  
  Все действия логируются с помощью модуля logging.
- Поддерживаемые команды:  
  /start, /list_cat, /find_cat, /add, /edit, /find
3. Руководство пользователя
- /start  — Запускает бота, выводит приветствие и описание возможностей.
- /list_cat  — Показывает иерархию категорий и количество рекомендаций (всего и ваших).
- /find_cat  — Позволяет искать и управлять категориями: находить по id/ключевому слову, добавлять, изменять, удалять.
- /add  — Добавить новую рекомендацию: выберите категорию и введите текст рекомендации.
- /edit  — Поиск и редактирование своей рекомендации: выберите категорию, найдите свою рекомендацию, измените её название или текст.
- /find  — Поиск рекомендаций по id/ключевому слову в выбранной категории, возможность редактировать/удалять свои рекомендации.
*Используйте кнопки или вводите ответы по запросу бота согласно подсказкам.*
4. Руководство администратора
- Изменение структуры категорий:
  - Через /find_cat можно добавлять, изменять, удалять категории (при отсутствии чужих рекомендаций).
- Управление пользователями:
  - Все пользователи Telegram автоматически идентифицируются по user_id.
- Резервное копирование:
  - База данных (файл .db) может быть скопирована для бэкапа.
- Просмотр логов:
  - Логи сохраняются в файле (например, bot.log). Используйте tail -f bot.log для мониторинга.
- Добавление администраторов:
  - Cписок admin_id хранится в config.env, пока в проекте он не использовался (включить его не сложно).
- Настройка .env:
  - Замените TELEGRAM_TOKEN на свой токен для смены бота.
5. Описание интеграции с базой данных
- База: SQLite, файл comments.db (имя может быть другим).
- Таблицы:
  - categories: id, parent_id, name
  - users: id, name, telegram_id
  - comments: id, name, comment, user_id, category_id
- Взаимодействие:
  - Все операции с категориями и рекомендациями выполняются через методы SQL.
  - FSM-класс использует эти методы для чтения/записи данных в процессе сценариев.
- Резервное копирование:  
  Просто копируйте файл базы данных.

6. Описание проведенных тестов для основных сценариев работы
Тестирование проводилось вручную 
Основные сценарии:
- /start
  - Ожидаем приветственное сообщение и меню.
- /list_cat
  - Проверка отображения иерархии категорий и чисел рекомендаций.
- /find_cat
  - Поиск категории по id/ключевому слову, просмотр подкатегорий.
  - Добавление, изменение, удаление категории (при отсутствии чужих рекомендаций).
- /add
  - Добавление рекомендации: правильная привязка к категории, корректное сохранение.
- /edit
  - Изменение собственной рекомендации: поиск по id/ключу, корректное изменение.
  - Проверка, что нельзя изменять чужие рекомендации.
- /find
  - Поиск рекомендаций, проверка возможности редактирования/удаления только своих.
- FSM
  - Проверка возврата по стеку, восстановления состояния процесса при возврате назад.
- Пограничные случаи
  - Попытка удалить категорию с чужими рекомендациями — ошибка.
  - Попытка изменить чужую рекомендацию — ошибка.
  - Корректность перехода состояний FSM.
